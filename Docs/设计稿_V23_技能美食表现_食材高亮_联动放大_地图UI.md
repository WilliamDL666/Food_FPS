## 0. 设计意图

| 需求 | 要解决的体验问题 |
| --- | --- |
| ① 技能美食表现 | V21 换了名字和模型，但**用的那一下**还不像美食：第一人称没有施放动作，音效是现有音效变调，命中 / 生效没有"吃到了"的反馈，技能图标没换。要做到**闭着眼听也知道是哪道菜**。 |
| ② 食材高亮 | V21 告诉了玩家"差一样：鸡蛋"，但没告诉他**鸡蛋在哪**。食材随机刷新，玩家只能满图找。要做到：手上拿一样，**一抬头就知道下一样去哪拿**。 |
| ③ 联动放大 | V22 的 6 个联动规则对，但**幅度小**：蒸汽阀挡视线半径约 2.7 m，芥末辣锅 6 m。用户感受是"触发了，但没改变战局"。要做到：**触发一次，全队都能感受到局面变了**。 |
| ④ 人人有联动 | 6 个干员都有主联动，但**出现频率**差很多：铆钉开局场上 0 个破口，夜鸦只有 2 口锅，焚芯只有 2 面蛋糕墙。要做到：每人每回合至少有 1 次机会。 |
| ⑤ 地图 UI | 小地图 / M 大地图是灰底黑方块的"工程图"，和粉色美食街完全两种风格，信息层级混乱。要做到：**像 MAP-A1 一样一看就是美食街，同时比现在更好读**。 |

四条原则：
1. **技能表现只改表现**。规则、数值、时长、可听距离、透明度都不动（沿用 V21 原则）。
2. **提示要"能用"，也要"不吵"**。高亮有上限、有主次、交火时降低。
3. **放大强度，同时放大反制**。每个放大项都配一个同样一眼能看懂的反制，强度锁在地图点位上。
4. **地图 UI 先定信息层级，再定画风**。

### 1.2 食材：知道缺什么，不知道在哪

| 项 | 现状 | 证据 |
| --- | --- | --- |
| 刷新规则 | 18 个固定刷新点；每个点被拿走后 16 s（抢食 8 s）再刷；**13 种食材等概率随机**；回合开始 0–4 s 内刷出 | `FoodPlay.cs` 388–402；`Arena.cs` 756–760 |
| 能配上的概率 | 奶茶三件套各有 2 个搭档，其余 10 种各 1 个 | `Ingredients.Recipe` |
| "地图上根本没有搭档"的概率 | 18 个点全满时：单搭档食材 (12/13)^18 ≈ **24%**；奶茶类 (11/13)^18 ≈ 5%。实际有人在拿，场上常驻约 10–12 个时：单搭档 ≈ **38–41%** | 按上面规则计算 |
| 现在的提示 | 气泡写配方（12 m 内）、绿 = 能配 / 灰 = 配不上；HUD "差一样：鸡蛋 → 巨型蛋糕" | `FoodMarkers.cs` 42–47；V21 M23 / M25 |
| 缺的 | 世界里远处看不出哪个是搭档（38 m 外气泡就隐藏）；小地图没有任何食材图标；没有方向指引 | `FoodMarkers.cs` 110；`GameUI.cs` 434–494 |

> 结论：只做高亮，约 **四成时间高亮"没东西可亮"**。高亮和刷新规则要一起改（§3.4）。

## 2. 技能美食化表现（规则和数值不动）

### 2.1 统一约束（表现不能改变规则）

| 约束 | 内容 | 为什么 |
| --- | --- | --- |
| 动作时长 ≤ 现有锁定时间 | 冲刺前摇 0.15 s、威化部署 0.6 s 可以完整用来做动作；签子、纸杯、迷雾、布丁盾是"按下即生效"，**动作只用左手，0.25–0.4 s，枪保持可开火** | 不新增"不能开火"的时间，否则就是改规则 |
| 可听距离不降 | 冲刺 40 m、布丁盾 45 m、引信 35 m / 0.15 s、迷雾 45 m、扫描 45 m 不变 | 反制靠听（V21 原则） |
| 透明度不降 | 布丁盾、棉花糖迷雾保持现有半透明 | 现规则"不挡视线" |
| 颜色语义不变 | 纸杯红色预警圈保留；金色只给联动 | V21 / V22 约定 |
| 判定不变 | 签子碰撞球 0.35 m、纸杯直径约 0.3 m | 打掉签子的难度不变 |

### 2.2 逐个干员

每个干员一张表：施放动作（第一人称 / 第三人称）→ 特效 → 音效 → 生效反馈（给自己）→ 敌方怎么读。

#### ① 猎隼 · 汽水冲刺

| 项 | 现状 | 改后 | 为什么 |
| --- | --- | --- | --- |
| 第一人称 | 枪模不动 | 前摇 0.15 s：左手从腰间掏出汽水罐**摇两下**，拇指"啵"开拉环；冲刺 0.2 s：罐口朝后喷，屏幕边缘一圈焦糖色气泡流 | 前摇本来就有 0.15 s，动作刚好填满，玩家第一次能"看见"前摇 |
| 第三人称 | 角色直接位移 | 身后拉出一条 3–5 m 的**可乐尾迹**（棕色 + 白色气泡），0.6–0.8 s 消散 | 敌人能看到"从哪冲过来的" |
| 特效 | 气泡 + 可乐粒子 | 加**气泡残影**（2–3 个半透明气泡色人形，间隔 0.06 s）；落地脚下一圈**可乐泡沫水渍**，存在 1.5 s（= 减伤时间） | 水渍存在的时间 = 减伤时间，敌人看地面就知道他还有减伤 |
| 音效 | `food_fizz` + 0.35 音量 `thrusterFire` | 前摇：**新合成"摇罐 + 开罐"**；冲刺：气泡喷射；落地：**新合成"饱嗝"**（0.3–0.5 s，低频共振峰） | 开罐和饱嗝是这个技能的"签名音"，闭眼也能认出来 |
| 生效反馈 | 无 | 冲刺后 2.5 s 内造成伤害（= 现有 `skillEffective` 判定）：准星下飘字"续杯！" | 和 V22 "结果字 = 遥测有效判定"同一套 |
| 敌方怎么读 | 只靠声音 | 开罐声 + 尾迹 + 落地水渍 | 三个信号都指向同一件事 |

> **⚠ 冲突（旧测试）**：去掉 `thrusterFire` 那层会让旧测试 T01（用 `thrusterFire` 判定冲刺启动音）失败。默认**保留那层但音量降到 0.15–0.2**；如果你同意改 T01 的断言（改成判定新的开罐音），就彻底去掉。

#### ② 铆钉 · 威化饼干墙

| 项 | 现状 | 改后 | 为什么 |
| --- | --- | --- | --- |
| 第一人称 | 枪模不动 | 部署 0.6 s：左手把爆米花机倒过来"挤"，奶油条往前喷，镜头轻微下点头 1 次 | 部署时间本来就 0.6 s，动作填满，也让玩家知道"这 0.6 s 我在干活" |
| 第三人称 | 墙直接出现 | 威化**分 3 层从下往上叠**（每层 0.2 s），每层之间挤一条队伍色奶油 | 敌人能看到"墙还没叠完"，就是打断窗口 |
| 特效 | 2/3、1/3 掉渣 + 变暗 | 2/3、1/3 出现**真的裂缝贴花**（3 段破损模型）；被打中处掉小块威化屑；碎掉时整面墙"哗"地散成十几块饼干，落地 2–3 s 后消失 | 血量变成形状，不用看数字 |
| 音效 | `food_squish` + `food_popcorn` | 每叠一层一声**新合成"咔嚓"**（脆）；落地最后一层加一声低频"咚"；被打：小脆响；碎：大"哗啦" | 3 声咔嚓 = 3 层 = 0.6 s 部署，节奏可读 |
| 生效反馈 | 无 | 墙挡住 ≥ 60 伤害（现有判定）：飘字"威化挡住了！" | — |
| 敌方怎么读 | 只看到墙 | 叠层过程 + 裂缝 | — |

#### ③ 铁幕 · 焦糖布丁盾

| 项 | 现状 | 改后 | 为什么 |
| --- | --- | --- | --- |
| 第一人称 | 枪模不动 | 左手往前一推，盾"啵"地从地面弹起：先压扁到 60% 高再回弹到 110% 再落到 100%（0.25–0.35 s，盾在第 1 帧就生效） | 布丁的"Q 弹"靠形变表现，不靠颜色 |

## 3. 食材高亮

### 3.1 规则（玩家看得到的）

| 规则 | 内容 |
| --- | --- |
| 什么时候亮 | 手上**正好 1 样**食材时；空手和已凑成（变身中）都不亮 |
| 亮谁 | 地图上**当前存在**、能和手上那样凑成菜的食材（`Recipe(held, id) != Dark`）。包括刷新点上的和别人阵亡掉落的 |
| 不亮谁 | 凑不成的（只走 V21 灰色气泡）；别人手上拿着的 |
| 只给自己看 | 高亮是个人信息，队友、敌人都看不到你的高亮 |
| 三层表现 | 世界里：描边 + 光柱；小地图：食材图标；屏幕边缘：方向箭头 |

| 实时更新 | 新刷出来的搭档 0.5 s 内出现；主目标被别人捡走，0.5 s 内切到下一个，并飘一行"鸡蛋被抢走了 · 换一个" |

### 3.3 排序和防刷屏

**排序**：按**路径距离**（`NavMesh.CalculatePath`，0.5 s 算一次；算不出时用直线 × 1.3）从近到远。

| 防刷屏规则 | 值 | 理由 |
| --- | --- | --- |
| 同时最多 | 主 1 + 备选 2 = **3 个** | 再多就成了"满屏光柱"；奶茶类最多 2 种搭档，3 个够用 |
| 主目标切换门槛 | 新候选比当前主目标近 **20–30%**，或近 **8–12 m**，才切换 | 两个距离差不多时来回跳很烦（滞后） |
| 走到 12 m 内锁定 | 锁定后不再切换，直到捡到或消失 | 快到了就别换 |
| 交火降噪 | 最近 **1.5–2.5 s** 开过火或受过伤：箭头和光柱透明度降到 **25–35%**；开镜时箭头隐藏 | 和 V21 `FoodTips.CombatQuiet` 同一个判定 |
| 新刷出提示 | 新搭档出现时，小地图图标"弹"一下 + 轻提示音；**每 8–12 s 最多 1 次** | 告诉玩家"有新的了"，但不连响 |
| 和联动星的区别 | 联动 = 金色星；食材 = 食材本色圆形图标 | 两种信息颜色、形状都不同 |
| 设置开关 | "食材指引：全部 / 只小地图 / 关" | 老玩家可以关光柱 |

**AI**：`Bot.FoodGoals` 已经只去捡能自动捡的（V21）。高亮用同一个静态函数 `FoodGuide.Partners(held)` 算候选，AI 和玩家看到的"可捡集合"完全一致，不会出现 AI 作弊或玩家更占便宜。

### 3.4 刷新规则：保持，还是改成随机池？

| 方案 | 规则 | 取舍 |
| --- | --- | --- |
| 甲 · 保持现状 | 18 个固定点，13 种等概率 | 0 改动；约四成时间"高亮没东西亮"，高亮的价值打折 |
| **乙 · 随机 + 保底（推荐）** | 点位不变。刷新时：①用**洗牌袋**（13 种各 1 张，抽完再洗）代替纯随机，保证各种食材出现频率一致；②**配对保底**：有人手上拿着 X、地图上没有 X 的搭档时，下一次刷新有 **50–70%** 概率刷成 X 的搭档，刷新点从离这个人 **25–40 m** 的点里随机挑 | 改动小（`IngredientSpot.Update` 一处）；高亮几乎总有东西可亮；保底刷得不近不远，**还是要跑一段路**、穿过交战区；AI 一样受益 |
| 丙 · 随机点位池 | 加到 26–30 个候选点，每次从里面随机挑 18 个刷 + 乙的保底 | 位置更难背，"随机刷新"感最强；要 level-designer 再选 8–12 个点，AI 路线和截图要复核；工作量多 0.5–1 天 |

> 推荐乙：用户说的"东西是随机刷新的"本来就成立，真正的问题是"随机到没有搭档"。保底只修这一点。

## 4. 联动影响力放大

### 4.0 先修两个隐患（放大的前提）

### 4.1 蒸汽阀 / 火锅（需求 3a）：从"一团白雾"到"整片看不见"

| 规则 | 现在 | 改后 |
| --- | --- | --- |
| 触发 | 蒸汽阀长按 G 0.5 s | 不变；**新增**关口两口火锅各一个"开大火"旋钮（长按 G 0.8 s），喷出同款整片蒸汽 |
| 范围 | 挡视线约 2.7 m | **整片**：中庭蒸汽阀 8–10 m、南后厨 6–8 m（巷宽 6 m，整条巷 20 m 长基本盖满）、关口火锅 8–10 m。**判定半径 = 显示半径**（新类型不再 × 0.8） |
| 外面看里面 | 能看到 | **完全看不见**：玩家和 AI 都看不穿 |
| 里面看外面 / 里面看里面 | — | 只能看清 **2–3 m** 内的轮廓，更远看不见。玩家镜头进入时屏幕整体泛白（中心透明度 85–95%） |
| 子弹 | 穿过 | 不变：可以盲射 |
| 爆炸 | 现在被热气挡住（隐患 1） | 修好后：**手雷、纸杯照样炸得到**——"往雾里扔雷"是标准反制 |
| 时长 | 6 s | 8–12 s；0.8–1.2 s 膨开，最后 1–1.5 s 变薄 |
| 冷却 | 25 s | 35–45 s（更强所以更长） |
| 关阀（新反制） | — | 任何人走到正在喷的阀门 / 旋钮前长按 G 0.5 s 关掉，蒸汽 1.5–2 s 内散开。**阀门在雾的中心**——关阀的人得自己走进看不见的地方 |
| 地图显示 | 无 | 小地图 / 大地图上画白色半透明的雾区 + 剩余时间环，**双方都看得到** |
| 叠加 | — | 同一片区域不叠加时长；全图同时最多 **2 片**整片蒸汽 |

**AI 视线**：AI 走 `SightClear`，外面看不进、里面只看 2–3 m，和玩家一致。AI 在雾里改为"听声索敌"（`Bot.Hear` 已有）。

**为什么这样定**：
- 8–10 m 正好盖住中庭两个连廊口（中庭蒸汽阀在 (16, ±8)，A / B 连廊口在 x 14–26、z ±10–24），是攻方过中庭最需要的那一片。
- 里面保留 2–3 m 而不是全黑：全黑会让人迷路，迷路不是"战术"，是"难受"。
- 关阀是"高风险高回报"的反制：守方可以花一个人冒险进去关，也可以等 8–12 s。

### 6.3 三套底图方案

#### 甲 · 按真实几何渲染俯视图 + 美食调色

| 项 | 内容 |
| --- | --- |
| 做法 | 回合开始时（或场景生成后）用一台**正交相机从正上方渲一次**到贴图（1024–2048 px 宽，7–14 px/m）。**近裁剪面放在离地 4–5 m**，等于把楼顶"切掉"，能看到 B 厂房、南后厨这些室内。排除角色、粒子、气泡、标记层。再过一遍调色：地面映射成奶油粉，墙顶描奶油滴边，按高度分 3 档亮度 |
| 高于切面的东西 | 市场楼顶（8 m）、空中连廊（8.9 m）、奶油平台（3.5 m，在切面以下）——前两个用矢量轮廓叠加画回去 |
| 运行时还是离线 | **运行时**（推荐）：地图怎么改，底图自动跟着变，不用维护资产；渲一次约 1 帧，贴图 4–16 MB。离线（`BuildDemo` 打包时渲成 PNG）：画质能更高、能用烘焙光照，但每次改关卡都要重渲 |
| 可读性 | 高：玩家在地图上看到的颜色就是街上看到的颜色（"粉色波点那栋楼"），定位最快；缺点是细节杂（糖粒地面、招牌），要模糊 / 色阶化处理 |
| 美食风格 | 中高：天然就是美食街的颜色，但没有 MAP-A1 那种手绘感 |
| 工作量 | 2–3 天（相机 + 切面 + 调色 shader + 叠加层） |
| 风险 | 中：层级（Layer）要整理，现在大多数物体在默认层；粒子 / 光照烘焙暗角会脏；切面高度要逐区域调 |

#### 乙 · 程序化矢量底图（路线色块 + 图标）

| 项 | 内容 |
| --- | --- |
| 做法 | 从关卡数据画：建筑 = 圆角奶油色块 + 投影 + 奶油滴边；三条路线各一种底色（北长街桃色、主街薄荷绿、南长街薰衣草紫，对齐 MAP-A1 中路绿色）；高台用双描边；图标用统一的美食图标集 |
| 数据来源 | 现有 `minimapBlocks` **远远不够**（只有 5 处登记）。要求 `Arena.cs` 里每个生成实体几何的地方都登记：建筑、墙、矮掩体、平台（带高度）、坡道、门 |
| 可读性 | 最高：像《无畏契约》的地图，路线一眼分清，噪声最少 |
| 美食风格 | 中：靠配色和图标撑，扁平 |
| 工作量 | 2–2.5 天 + 0.5–1 天登记审计 |
| 风险 | 中高：**底图和真实几何会漂移**——以后谁加了几何忘了登记，地图就错。需要一个自动测试兜底（§8 M56） |

#### 丙 · 手绘风格贴图（MAP-A1 那种）

| 项 | 内容 |
| --- | --- |
| 做法 | 按方案甲渲出的俯视图做底稿，美术（或生图 + 修图）画一张**正俯视**手绘图，4 个控制点对齐世界坐标 |
| 可读性 | 中：最好看，但细节多、斜角透视会挡住街道 |
| 美食风格 | 最高，截图和面试展示效果最好 |
| 工作量 | 接入 1 天 + 美术 2–4 天；**每次改关卡都要重画** |
| 风险 | 高：①MAP-A1 是 45° 斜视角，高楼会挡住后面的街，**不能直接当地图用**，必须重画成正俯视；②V22 刚改完一轮布局，后面还会改；③对齐误差 1–2 m 就会把图标画到墙里 |

#### 对比与推荐

| 维度 | 甲 渲染俯视 | 乙 矢量 | 丙 手绘 | **甲 + 乙叠加（推荐）** |
| --- | --- | --- | --- | --- |
| 和真实几何一致 | 自动一致 | 靠登记 | 靠重画 | 自动一致 |
| 可读性 | 高 | 最高 | 中 | 最高 |
| 美食风格 | 中高 | 中 | 最高 | 中高 |
| 维护成本 | 低 | 中 | 高 | 低 |
| 工作量 | 2–3 天 | 2.5–3.5 天 | 3–5 天 | **3–4 天** |
| 风险 | 中 | 中高 | 高 | 中 |
| 面试讲法 | "地图 UI 从真实几何生成" | "信息层级" | "美术表现" | "底图从几何生成保证正确，矢量层保证可读" |

**推荐：甲 + 乙叠加。** 底图用甲（运行时渲染 + 美食调色，保证永远和关卡一致），上面叠乙的**结构线和图标层**（高台描边、门、路线色调、图标），只登记"要强调的东西"，不用登记全部几何，漂移风险小。小地图把底图饱和度降 40–60%、结构线加粗；大地图全彩。丙留作以后"宣传图 / 加载画面"，不当功能地图。

## 9. 面试讲解卡

### 卡 1 · 地图 UI：底图从几何生成，信息靠层级
- **问题**：小地图是灰底黑方块，只画了 5 处登记过的方块，V22 新加的平台、横幅都不在图上；横纵比例还差 10%。大地图 23 个区域名互相压，图标是军事物件。
- **我的做法**：底图用正交相机运行时从真实几何渲出来，切掉 4–5 m 以上看到室内，再调成美食配色；上面叠一层矢量结构线和美食图标。先定 9 层信息层级，小地图只放"现在要用的"。
- **为什么**：手绘图好看，但关卡一改就错；纯矢量好读，但靠人登记会漂移。生成 + 叠加两头都要：正确性交给程序，可读性交给设计。用自动测试保证"95% 可走点落在地面色上"。

### 卡 2 · 食材高亮：提示要"有东西可提示"
- **问题**：V21 已经告诉玩家"差一样：鸡蛋"。但我算了一下：13 种食材等概率刷，场上约 11 个时，**约四成时间地图上根本没有鸡蛋**。只做高亮，玩家会经常看到"什么都没亮"。
- **我的做法**：高亮分主次（主 1 + 备 2），路径距离排序，加切换滞后和交火降噪；刷新改成洗牌袋 + 配对保底：有人缺鸡蛋时，下一次 50–70% 刷鸡蛋，刷在 25–40 m 外。
- **为什么**：引导系统的前提是"目标存在"。保底不是白给，刷在中距离就是让玩家穿过交战区去拿——高亮把"满图乱找"变成"选路线"。

### 卡 3 · 联动放大：强度和反制一起放大
- **问题**：用户觉得地图交互影响太小。蒸汽阀实际只挡 2.7 m，芥末辣锅只盖锅边。但放大前我发现，"挡视线"和"挡爆炸"用的是同一个函数——蒸汽一放大就成了防爆罩，最自然的反制"往雾里扔雷"会失效。
- **我的做法**：先把视线和爆炸判定拆开；再把蒸汽放到 8–10 m、芥末放到 12 m；每个放大都配一个同样直观的反制：进雾关阀、芥末味穿透蒸汽、糖味盖芥末。加两条硬约束：每个包点至少 2 个常规入口不能被封，全图最多 2 片盲区，并且盲区双方地图上都看得到。
- **为什么**：放大的风险是"无解组合"。我先推演了 4 个最坏组合，每个都有出路，再给出三档数值让用户选。强度锁在地图点位上，守方能预判。
