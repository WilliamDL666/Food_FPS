## 0. 设计意图

| 项 | 内容 |
| --- | --- |
| 体验目标 | **规则里已经存在的每一个"等待"和"状态"，玩家都能在 0.2 秒内从屏幕或声音里读出来**，不用猜"为什么开不了枪、为什么跳不起来、为什么我死了"。 |
| 面试讲法 | "V20 的 3C 和技能规则都做了，但很多规则是**隐藏时间**：冲刺转开火、趴下切换、开镜都在走计时，屏幕上却没有任何变化。V22 的原则是**表现时长 = 规则时长**、**HUD 不用时隐藏、关键时出现**、**敌我看到不同的信息**。" |

三条设计原则：
1. **表现时长 = 规则时长**。手部动作、镜头、准星的过渡时间直接读规则参数（`sprintToFire`、`AdsTime`、`ProneTransition`），不再用写死的插值速度。
2. **不用时隐藏，关键时出现**。满体力、站立、未超重时这些元素都不画；跨过阈值（耗尽、超重、被侦测）时才出现，并且带声音。
3. **规则 0 改动**。所有改动只碰表现层；唯一涉及手感规则的"开火输入缓冲"单独列为拍板项。

**结论**：问题集中在三类——
- **隐藏计时**（1–4、10、11）：规则在跑，表现没跟上。
- **信息错误**（13、14、21、22）：给了玩家错误答案，比不给更糟，优先修。
- **单向信息**（15–20）：施放者和被施放者之间缺少"我做了什么 / 我该怎么反制"的对称设计。

## 2. 3C 反馈优化

### 2.1 HUD 布局（1920 × 1080 参考）

原则：**动态状态贴准星，静态信息放边角**。眼睛在交火时只看屏幕中心约 300 像素范围，所以"会在交火中变化、需要立刻决策"的东西（体力、能不能开火、姿态切换）放到准星下方的**状态带**；生命、弹药、技能这类"偶尔看一眼"的留在下方两角。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [小地图 270×190]               [顶栏：比分 / 计时]            [击杀播报 ×7]  │
│ [当前位置]                                                                    │
│                       [敌方大招横幅（新，2 s）/ 变身横幅]                     │
│                       [被施放状态条（新）：被芥末呛到 3.2s ▓▓▓░]              │
│                                                                              │
│                                                                              │
│  ◀ 受击弧（最多 3 个）              ┼  准星                  受击弧 ▶        │
│                              ◜ 就绪 / 换弹 / 姿态切换环 ◝                    │
│                                                                              │
│                         ─── 状态带（新，准星下 60–90 px）───                 │
│                         [体力条 160px ·····|·········]  ← 25% 刻度          │
│                         [姿态图标] [◀ 探头 ▶] [滑铲冷却点]                  │

│ [大招条 ■■■■□ X 就绪]                                                       │
│ ┌英雄面板──────────────────────┐                ┌武器面板────────────────────┐│
```

| 区域 | 内容 | 显示规则 |
| --- | --- | --- |
| 状态带 | 体力条、姿态图标、探头箭头、滑铲冷却 | **全部默认隐藏**；站立 + 满体力 + 不探头时这一带是空的 |
| 准星环 | 冲刺转开火 / 拔枪 / 姿态切换 / 换弹进度 | 同一时间只画一个，优先级：换弹 > 姿态切换 > 拔枪 > 冲刺转开火 |
| 被施放状态条 | 被芥末呛到、被糖黏住、被焦糖火烫 | 只在生效时显示，带倒计时 |
| 英雄面板 | 减伤、盾耐久等"自己技能的持续效果" | 只在生效时显示 |
| 武器面板 | 超重标签 | 只在超重时显示 |
| 旧的左侧"姿态 / 负重"文字 | — | **删除**（`CombatModel.cs:423`），同时解决和变大模式文字重叠 |

### 2.2 逐项设计

每项格式：**玩家状态 → 现在 → 改后（HUD / 镜头 / 音效 / 手部）→ 为什么 → 行业参考**。

#### ① 姿态指示

| 项 | 内容 |
| --- | --- |
| 玩家状态 | 站 / 走 / 蹲 / 趴 / 滑铲 / 冲刺 / 翻越 / 空中 |
| 现在 | 左侧一行小字"姿态：蹲下"，常驻；镜头高度 0.2 秒到位 |
| 改后 · HUD | 状态带中间一个 28–32 px 美食图标：**蹲 = 饭团**（矮一截）、**趴 = 煎饼**（"摊成煎饼"，和 V21 优化稿用语一致）、**滑铲 = 黄油块**、**冲刺 = 汽水泡**。站立 / 行走不显示。切换瞬间图标放大 1.3 倍再回落（0.15 秒）|
| 改后 · 镜头 | 镜头高度过渡改为按规则时长：趴下 / 起身用 `ProneTransition`（0.45 秒，前快后慢），蹲下保持现在的速度 |
| 改后 · 手部 | 趴下时枪模下沉 + 往里收；蹲下时轻微下沉 2–3 cm。切换期间枪口微微偏下，到位后抬平——**"枪抬平 = 能开枪"** |
| 改后 · 音效 | 蹲：布料摩擦（轻）；趴：身体着地"啪"（food 模式用软一点的 `food_squish`） |
| 为什么 | 姿态是"速度 / 判定框 / 精度"三者交换的核心选择，玩家要随时知道自己在哪一档；但站立是默认态，不需要显示 |
| 行业参考 | 战术射击（如三角洲、彩虹六号类）普遍在 HUD 角落或准星附近用小人剪影表示站 / 蹲 / 趴；只显示非默认姿态是常见的降噪做法 |

#### ② 体力条

| 项 | 内容 |
| --- | --- |
| 玩家状态 | 冲刺消耗中 / 恢复延迟中（停下后 0.8 秒）/ 恢复中 / 耗尽锁定（< 25 不能冲）/ 满 |
| 现在 | 不满就显示，220 × 7，在 H−128；耗尽变红 + 一行字 |
| 改后 · HUD | 移到状态带，宽 140–180、高 4–6。**25% 位置画一条刻度线**（= `ExhaustRecover`）。四种颜色：消耗中白、恢复延迟中灰（条不动，提示"还没开始回"）、恢复中浅绿、耗尽锁定红色闪烁（2–3 Hz）。回满后 0.8–1.5 秒淡出 |
| 改后 · 低体力预警 | 冲刺中体力 < 25：条变黄，刻度线亮——"再冲就会被锁" |
| 改后 · 跳跃 / 翻越 | 每次扣体力时，条上被扣掉的那一段先变白再消失（0.3 秒），让"跳一下 −8"看得见 |
| 改后 · 音效 | 耗尽瞬间一声喘气；锁定期间轻微喘息循环，恢复到 25 时停（这个停顿本身就是"可以冲了"的信号）|
| 改后 · 手部 / 镜头 | 耗尽锁定期间枪模晃动幅度 ×1.3–1.5（只是表现，不影响散布）|
| 为什么 | 体力的决策点是两个阈值：**0（被锁）和 25（解锁）**。现在只显示了数量没显示阈值；放到准星下方，是因为体力在交火中就要用（冲刺换位） |
| 行业参考 | Apex、COD、三角洲类射击常见做法：体力 / 冲刺条只在消耗时出现、满了自动隐藏；耗尽用呼吸声代替文字，玩家不用低头看 |

#### ③ 冲刺转开火等待（本稿重点）

| 项 | 内容 |
| --- | --- |
| 玩家状态 | 冲刺刚结束，`Time.time − sprintEndedAt < sprintToFire`（0.10–0.32 秒），`CanFireNow = false` |
| 现在 | 准星立即恢复不透明；扣扳机被吞，无反馈 |
| 改后 · 手部（主信号）| 冲刺时枪口朝下 / 斜放（已有 `-18° / 12°` 姿势），**抬枪过程的时长 = 这把枪的 `sprintToFire`**：SMG-7 0.10 秒一甩就到，LMG-2 0.32 秒明显吃力 |
| 改后 · 准星 | 冲刺中 0.2 透明度（现状）；冲刺结束后在 `sprintToFire` 时间内从 0.3 线性升到 0.95，同时准星间距从 +6 px 收拢到正常——**准星收拢完 = 能开枪** |
| 改后 · 吞键反馈 | 等待期间扣扳机：准星中心闪一下灰点（0.1 秒），不出声或极轻的空扳机声（见拍板 2）|
| 改后 · 音效 | 抬枪到位时一声轻的"咔"（枪械握持音，音量 0.15–0.25，只自己听得到）|
| 为什么 | 这段时间是规则故意给守点方的反应窗口（战斗设计文档 §2.1），不能取消；但**代价必须看得见，才会被玩家当成"取舍"而不是"bug"**。用抬枪动画表达是因为它不占 HUD、也最符合直觉 |
| 行业参考 | COD / Apex / 三角洲类常说的 "sprint-out time"（冲刺转开火）：几乎都用武器从冲刺姿态抬回瞄准姿态的动画来表达，重武器抬得慢 |

#### ④ 开镜进度

| 项 | 内容 |
| --- | --- |
| 玩家状态 | 开镜中 `0 < adsK < 1`，时长 = `Ballistics.AdsTime`（受负重影响）|
| 现在 | 视野按 `adsK` 走，枪模用固定插值 0.15 秒到位；美食模式 `adsK < 0.85` 时屏幕中心没有准星；写实模式倍镜有 0.12 秒全黑 |

| 改后 · 倍镜 | 保留 0.12 秒黑场（防"秒镜"），但改成从边缘向内收的遮罩，不再整屏发黑 |

| 为什么 | 开镜时间是枪械定位的一条轴（§3.3），也是负重惩罚的主要体现；**表现比规则快，惩罚就被藏起来了** |
| 行业参考 | 主流 FPS 的 ADS 动画时长都直接等于 ADS 时间参数；配件 / 负重影响开镜速度时，玩家是从"举枪变慢"感受到的 |

#### ⑤ 负重

| 项 | 内容 |
| --- | --- |
| 玩家状态 | 未超重（≤ 8 kg）/ 超重（每 kg 移速 −1.2%、开镜 +3%）|
| 现在 | 左侧常驻"负重 4.2 kg" |
| 改后 · HUD | 未超重：不显示。超重：武器面板右下角琥珀色标签 **"吃撑了 · 移速 −6% · 开镜 +17%"**（美食化：重 = 吃撑）。买枪菜单里选中一把枪时预览"买了会吃撑多少" |
| 改后 · 手部 | 超重时走路晃动周期变慢 10–15%，幅度略大（只表现）|

| 行业参考 | 搜打撤类（三角洲烽火地带、塔科夫类）都把负重做成分档状态，超过档位才出现图标和减速提示；买 / 带装备前可以预览 |

| 项 | 内容 |
| --- | --- |

## 3. 干员技能体验优化

### 3.1 通用规则："施放者看效果，被施放者看反制"

| 信息 | 施放者 | 队友 | 敌人 |

## 7. 面试讲解卡

### 卡 1 · 冲刺转开火：把"隐藏时间"变成看得见的代价
- **问题**：冲刺停下后有 0.1–0.32 秒不能开火，这是给守点方的反应窗口；但屏幕上没有任何变化，玩家觉得"枪卡了"。
- **做法**：不改时间，只让枪从冲刺姿势抬起来的动画时长等于这个参数，准星同步从散开收拢到正常；没收拢时扣扳机只闪一个灰点。
- **为什么**：代价看得见，玩家才会把它当成取舍（"拿机枪就别冲着拐角"），而不是 bug。主流 FPS 都用抬枪动画表达 sprint-out time。

### 卡 2 · 表现时长 = 规则时长
- **问题**：开镜、趴下的视野和精度按规则走，枪模和镜头却用写死的插值速度，比规则快一倍；负重让开镜变慢，玩家却看不出来。
- **做法**：枪模、镜头、准星的过渡全部读同一个规则参数（`adsK`、`ProneTransition`），并写成自动测试：枪模到位时间和规则误差不超过 0.05 秒。
- **为什么**：手感问题很多是"表现和规则不同步"。把它变成可测指标，以后调任何一个数值，表现会自动跟上。

### 卡 3 · 体力条：不用时隐藏，阈值看得见
- **问题**：体力条只区分"满 / 不满"，在屏幕底部离准星很远；耗尽后要回到 25 才能冲，但条上没有这条线。
- **做法**：挪到准星下方，满了就淡出；画出 25% 刻度线；四种颜色区分消耗、等待恢复、恢复、锁定；耗尽时用喘气声代替文字。
- **为什么**：体力的决策点是两个阈值（0 被锁、25 解锁），HUD 要显示的是**阈值**而不只是数量；声音让玩家不用低头看。

### 卡 4 · 死亡回顾：给错答案比不给更糟
- **问题**：死亡回顾只记子弹。被焚芯的纸杯蛋糕炸死，标题却写"被上一个用枪打你的人击倒"。
- **做法**：所有伤害来源都写记录，标题用真实击杀者；加上"对手还剩多少血""你打了他多少"。
- **为什么**：死亡回顾的目的是让玩家知道为什么死、差多少；"差一点就赢了"是让人愿意再来一局的关键信息。这个问题是读代码发现的，不是测出来的——**先验证信息是对的，再谈信息够不够**。

### 卡 5 · 技能反馈：施放者看效果，被施放者看反制
- **问题**：技能"有没有用"只记在遥测里；被技能打的人只有右上角一行字，0.9 秒的反制窗口根本读不到。
- **做法**：施放者看到结果字（"呛到 2 人""没闻到人"），判断条件和遥测 `skillEffective` 是同一行代码；被施放者看到状态条、倒计时、方向箭头和一句反制方法。
- **为什么**：反制窗口只有在对手感知得到时才公平；HUD 和数据用同一个判定，调平衡时玩家体感和数据不会打架。
